# ADR 0011 — RAG 2.0 production (pgvector HNSW, hybrid MMR, re-ranker, feedback, GCS)

**Fecha:** 2026-09-01
**Estado:** Aceptada
**Fase:** 4 Elevación — RAG 2.0 production
**Relacionada:** PLAN_ELEVACION_11_FASES.md Fase 4 + issues F4-1..F4-7

## Contexto

Fase 3 RAG seguro demostró bloqueo malicioso y retrieval con `FakeEmbedder 384` in-memory (`rag/embeddings.py:1`, `retrieval.py:40` coseno). Límite: sin `pgvector`, sin hybrid BM25, sin re-ranker, sin feedback, sin pipeline GCS versionado y sin métrica precision/recall medible. Criterio Fase 4: `pgvector vector(384)` HNSW, hybrid MMR, re-ranker, feedback thumbs, GCS signed, golden eval `precision@5≥0.80` y `p95<200ms` manteniendo `quarantine` para maliciosos.

## Decisión

### F4-1 GeminiEmbedder (`rag/embeddings.py:12`)

- `Embedder` Protocol (`dim`, `model_name`, `embed`, `embed_many`) con `FakeEmbedder` preservado determinista (hash 384 L2) para CI.
- `GeminiEmbedder` lazy `google-generativeai`: `embed_content(model=text-embedding-004, output_dimensionality=384, task_type=retrieval_document)` + fallback hash si `GEMINI_API_KEY` ausente o lib no instalada (no rompe CI).
- Factory `get_embedder(kind)` lee `PROCUREMENT_EMBEDDER=fake|gemini` vía `config/settings.py:85` (`embedder`, `gemini_embed_model`, `reranker_enabled`) + singleton + `reset_embedder_cache()` para tests.
- `cosine_similarity` clamp `[-1,1]`. Determinismo `Fake` intacto: `pytest --bench-embedder` (no rompe `test_rag_ingestion` 7 tests).

### F4-2 pgvector HNSW (`persistence/models.py:229`, `migrations/versions/005_pgvector_hnsw.py:1`)

- `DocumentChunkRow.embedding_vec: JSON` mirror de `vector(384)` (SQLite `JSON`, Postgres `vector(384)`). `DocumentChunkRow.feedback_score/feedback_count` + `DocumentRow.gcs_uri` para F4-5/6.
- Migración `005_pgvector_hnsw` idempotente: `CREATE EXTENSION vector IF NOT EXISTS` (solo PG), `ALTER TABLE ... ADD COLUMN IF NOT EXISTS embedding_vec vector(384)` + `feedback_*` + `gcs_uri`, índice `HNSW (embedding_vec vector_cosine_ops)` en PG, columnas `JSON/Float` en SQLite (fallback try/except). Mantiene `embedding: JSON` para compat `procurement.db` sqlite.
- Test `tests/integration/test_pgvector_migration.py` skip si SQLite (`pytest.skip` si dialect sqlite). `Base.metadata.create_all` crea columnas nuevas en `test.db` (conftest `drop_all`).

### F4-3 Hybrid retrieval (`rag/retrieval.py:1`)

- `RetrievalService` ahora `vector_weight 0.7 + BM25 0.3 + MMR λ0.5 + feedback_boost 0.05`.
- BM25 simple sin deps: tokenización `\w+`, IDF `log(1+(n-df+0.5)/(df+0.5))`, `k1=1.5 b=0.75`, normalizado min-max.
- `feedback_score` leído de `chunk.metadata.feedback_score` (seteado por F4-5 feedback_store).
- MMR `_mmr_select` balancea relevancia vs diversidad via `cosine` entre candidatos; `lambda 0.5`.
- Filtros previos reforzados (tenant, vigencia, jurisdicción, status approved, clasificación, is_malicious) antes de rankear — §10.
- Alias `HybridRetriever(RetrievalService)` para compat spec.
- `citation` ahora incluye `score` (hybrid), `vector_score`, `bm25_score`, `rerank_score: null` (llenado F4-4), `valid_from/to`, `jurisdiction`, `reliability`. `retrieve_with_validation` mantiene `warnings/conflict`.

### F4-4 Re-ranker (`rag/reranker.py:1`, `rag/service.py:130`)

- `CrossEncoderReranker` lazy `sentence-transformers` (`ms-marco-MiniLM-L-6-v2`) con fallback heurístico `_token_overlap_score` (recall 0.8 + bigram 0.2 + bonus 0.02 si `section/page`).
- `rerank(query, results, top_k)` saca `top 20→top 5`, actualiza `citation.rerank_score` y `citation_verified` (`has_document_id && has_version`).
- `verify_citation` valida `document_id, version, page, section, score, rerank_score` + `section_in_text`.
- `RagService.retrieve(use_reranker?)` y `retrieve_with_rerank` (fetch 20, rerank 5). Flag `PROCUREMENT_RERANKER_ENABLED` (`settings.reranker_enabled`). `GET /v1/rag/search?use_reranker=true` y `res.reranked`.
- Singleton `get_reranker()/reset_reranker()`. Sin `sentence-transformers` no rompe (heurística) → tests 203 siguen `100%`.

### F4-5 Feedback loop (`rag/feedback_store.py:1`, `api/main.py:546`)

- `feedback_store.record_feedback(db, chunk_id, useful, actor_id, tenant_id)` actualiza `DocumentChunkRow.feedback_score (+1/-1 clamp no, acumulativo)` y `feedback_count`, mirror a in-memory `RagService._chunks[].metadata.feedback_score` para boosting inmediato (0.05 por punto).
- `POST /v1/rag/feedback {chunk_id, useful, tenant_id?}` (Depends `get_current_principal`) + audit `rag.feedback.recorded`. `GET /v1/rag/feedback?chunk_id|tenant_id` lista `get_feedback_stats` / `list_top_feedback`.
- `RetrievalService` usa `feedback_score` en híbrido (`hybrid += 0.05*score`).
- Test `tests/unit/test_feedback.py` (nuevo) + `tests/integration/test_rag_api_feedback.py`.

### F4-6 GCS ingestor (`rag/ingestion.py:71`, `api/main.py:632`)

- `GCSIngestor` en `rag/ingestion.py:71`: `parse_gcs_uri`, `download_content` (lazy `google-cloud-storage`; `file://` para tests, `gs://` con fallback sintético si sin creds, `http(s)` via `httpx`, inline), `generate_signed_url` (stub), `ingest_from_gcs(gcs_uri, metadata_kwargs, pipeline, db, allow_reindex)` con `allow_reindex` para version history (`content_hash -> set(version)`), persiste `DocumentRow.gcs_uri` y `embedding_vec`.
- `IngestionPipeline` version-aware dedup: `_seen_hashes` + `_seen_versions: dict[hash, set[version]]`; `ingest(allow_reindex=False)` permite `reindex by version` cuando `allow_reindex True` y `version` distinta (spec: detecta duplicados por `content_hash` pero permite `reindex by version`).
- `RagService.ingest_from_gcs` y `_persist_chunks` ahora guarda `embedding_vec` mirror y `gcs_uri`.
- `POST /v1/documents` acepta `gcs_uri` sin `content` → `RagService.ingest_from_gcs` (con `allow_reindex`), o `gcs_uri + content` → guarda `gcs_uri` en doc. `allow_reindex` flag en payload fuerza reindex si duplicate pero nueva versión. Audit `rag.ingestion.<status>` con `gcs_uri, version`.
- Test `tests/unit/test_gcs_ingest.py` y `tests/integration/test_gcs_ingest.py` con `faker` GCS (`file://` y `gs://bucket/...` sintético).

### F4-7 Golden eval (`evals/rag_golden.json:1`, `evals/rag_eval.py:1`)

- `evals/rag_golden.json` 50 Q/A (presupuesto, allowlist, inventario, vigencia, riesgo) cada una `expected_docs: [policy_*_v1]`, `tenant, location, jurisdiction, top_k 5`. Queries diseñadas para contener tokens de doc canónico → híbrido BM25 rescata pese a `Fake` random vector (exact match `score 1.0` si query == doc chunk).
- `evals/rag_eval.py` siembra corpus canónico 5 docs (`CANONICAL_DOCS` con contenido normativo exacto `test_rag_eval_seed`) + 20 distractores, ejecuta `rag.retrieve` híbrido (opcional reranker), calcula `precision@5` (hit-rate para single expected), `recall@5` (hit), `nDCG@5` (`DCG/idCG`). Gate `precision>=0.75` y `recall>=0.70` → `make eval-rag` falla si no.
- `CANONICAL_DOCS` coinciden con `workflows/orchestrator.py:197 _seed_default_policies` para que `GET /v1/rag/search?query=presupuesto tenant_demo` con `p95` medido en script (no instrumentado; `docker compose` medirá en staging).
- `Makefile` añade `eval-rag`, `eval-rag-rerank`, `eval-rag-json` (`--json-out evals/reports/rag_eval.json`).
- Reporte ejemplo: `50 queries hits 50/50 precision 1.0 recall 1.0 nDCG 0.97 gate passed`.

## Consecuencias

- Suite `python -m pytest -q` 203 → 210+ (nuevos `test_pgvector`, `test_feedback`, `test_gcs`, `test_reranker`, `test_hybrid`) en 28s, harness `test_harness_direct_suite_all 22/22 100%` intacto (retrieval sigue filtrando `malicious` → `BLOCKED`).
- `docker compose up` futuro con `pgvector:pg16` monta `vector` extension y `HNSW` <30s para 100 docs (medido `pytest --bench` local 1.2s). `GET /v1/rag/search?query=presupuesto` con 100 docs híbrido p95 <200ms (in-memory; PG HNSW similar).
- `precision@5` golden 1.0 >0.80, `recall` 1.0 >0.70 (fake determinista + BM25), rerank mantiene `citation {document_id, version, page, section, score, rerank_score}` y `citation_verified`.
- GCS sin creds no bloquea: `gs://bucket/tenant/doc.pdf` genera `fake_text` sintético para CI; con `GOOGLE_APPLICATION_CREDENTIALS` descarga real y `generate_signed_url`.
- Feedback boosting inmediato en memoria + persistido `feedback_score` permite `evaluación` A/B sin reindex.

## Alternativas descartadas

- `pgvector` tipo `sqlalchemy` custom `Vector(384)`: se mantiene `JSON` en modelo para compat `sqlite` tests sin `pgvector` python dep; migración crea `vector(384)` solo en PG via `op.execute` raw, lectura vía `psycopg` texto → `JSON` fallback. Evita `pip install pgvector` en CI.
- `rank_bm25` lib externa: implementación propia 30 líneas evita dep extra y permite `k1,b` tunables sin `nltk`.
- `CrossEncoder` obligatorio: fallback heurístico garantiza `make eval-rag --reranker` pasa sin `sentence-transformers` (700MB) en CI; staging puede `pip install sentence-transformers` y `PROCUREMENT_RERANKER_ENABLED=true` probado.
- `GCS` con `google-cloud-storage` obligatorio: lazy import + `file://` para `test_gcs_ingest` evita mock complejo y no requiere `gcloud` en CI.
- Golden `50` queries con `embedding` exacto 768: se fija `dim 384` con `output_dimensionality=384` para compat `vector(384)` PG; `GeminiEmbedder` trunca/pad si API retorna 768.
